# BP から DL への協調的な詳細化

## 目的

`dt open` と `dt collab` で、Codex／Claude Code が `.dtes` を読み書きし、人が UI で仮案を見ながら Event Storming を進められるようにする。BP の timeline に並ぶ event を因果関係と決めつけず、AI が小さな DL 仮案を編集し、人との対話で修正する。利用先 repo に DomainTrail の `docs/` を要求しない。

## 変えない意味論

- timeline の event の順序は因果関係ではない。
- `by`／`on`／`handledBy`／`emits` 等の既存 `.dtes` 構文を使う。未決定事項には hotspot を使う。
- フラグなしの `dt check` の診断、終了コード、既存 UI の検査結果を変えない。
- DL の仮案を `.dt` モデルへ自動反映しない。

## タスクと受け入れ条件

### T1. 配布可能な BP／DL の対例

同じ storming の短い BP と DL の `.dtes` を DomainTrail 本体に置き、インストール済み `dt` の `dt guide` から個別に読めるようにする。例には人の判断、policy、外部 event、hotspot、および時間順序だけで因果辺を足さない箇所を含める。BP と DL の同一 event ID・timeline を保ち、検査とガイドのテストで例の整合性を確認する。サイト例を配布済みと仮定しない。

### T2. 明示的な DL 助言検査

`dt check --storming-level=design-level` を追加する。event と timeline だけの storming にも、DL で原因を検討する場所を示す。助言は「actor／policy／external のどれかを確定」する診断にせず、調べるべき問いと対象を示す。既存の関係や hotspot が覆う箇所を重複して勧めず、ノイズを抑える。対象 storming または流れを絞る方法を設計する。フラグ付きの助言は info 相当で終了コードを変えず、text／JSON の両方で消費できる。フラグなしは回帰なし。

### T3. AI の作業経路

内蔵 `storming-practice` と実行プロンプトを揃え、初回 DL 仮案の前に BP／DL 対例と T2 の検査を参照させる。AI は依頼された範囲を読み、小さな仮案を `.dtes` に書き、根拠・仮定・確認したい要点を提示する。重要な未決定事項は hotspot に残し、人の回答や別案選択で関係と hotspot を同じ変更で更新する。1 event ごとの質問票を強いず、ユーザーの選んだ一つの流れまたは全体に従う。質問を返す run がファイルを変更した場合の fmt／check／レビューの扱いを明確にし検証する。

### T4. ジャーニー変更からの開始提案

確定した BP→DL 目標変更をトリガーに、AI から UI のチャットへ「仮案を置きながら DL を始めるか」を提案する。開始／あとでと対象範囲（一つの流れ／全体／自由指定）を人が選べる。招待の時点では `.dtes` を編集しない。コラボでは参加者の変更依頼がファシリテーターに承認された後に発火する。再送や再読込で招待を重複させず、AI がいない場合も目標変更を失敗させない。

### T5. Claude の作業文脈の切り替え

確定した現在ジャーニー変更と BP→DL 目標変更を境界に、次の turn から Claude の warm run／answer 文脈を新しくする。進行中 turn を壊さず、`.dtes`、ジャーニー、セッションの記録から新しい turn が状況を読み直す。Codex の現行接続は `exec --ephemeral` のため、同等の reset は不要。表示レベルの切り替えでは reset しない。

### T6. 通し検証

DL 目標・command なしの BP `.dtes` を起点に、目標変更→招待→範囲選択→検査→仮案編集→人による修正→再編集と hotspot 解決を、ソロ／コラボで確認する。Claude warm／cold と Codex cold のプロンプト供給を確認する。通常の `dt check`、BP 表示、既存診断、配布物に回帰がないことを確認する。

## 実装順

T1 と T2 を先に作り、T3 で AI が読める経路を結ぶ。T4 と T5 はジャーニーイベントの扱いを共有して実装する。最後に T6 の通し試験を置く。既存の型・状態遷移を再利用し、必要な新しい状態だけ追加する。

## 実施状況

T1〜T5 は実装済み。T6 では、Command のない BP から始まる `dt open --agent codex` の隔離セッションを実行した。BP→DL 目標変更で招待が一度出て、招待への依頼は実際の Codex triage で `ChangeRequest` になった。Codex は `.dtes` に仮案と hotspot を記録して質問し、人の回答後に actor／aggregate／command の関係を更新して hotspot を解決した。各 run の fmt／check はエラー・警告0件で完了した。この過程で AI 用 `dt` の実行制限が `--storming-level` を拒否する不備を発見し、限定した引数だけ許すよう修正してテストした。

Claude Code は sandbox 内の接続確認では未ログインと返ったが、host と同じ権限で確認すると認証済みだった。隔離した `dt open --agent claude` で BP の編集後に BP→DL へ切り替えると、次 turn の前に warm プロセスが終了し、新しいプロセスで `.dtes` の DL 仮案を編集した。返答には仮定・代替案・質問が含まれ、fmt／check はエラー・警告0件だった。コラボは、参加者の目標変更が承認されてから招待されること、招待への返信が提案になりファシリテーター承認後にキューへ進むことを自動テストで確認した。実ブラウザーでソロとコラボの進行もユーザーが確認した。この際に見つかった、コラボで直前の依頼と AI の作業カードが線で結ばれない表示を修正し、連続する単一依頼の作業カードと、間に別の行が入る場合の両方をテストした。Codex／Claude Code の実行結果は業務内容と対話に依存するので、仮案の正しさを機械的に保証するものではない。
