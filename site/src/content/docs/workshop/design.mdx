## 置くもの

| 付箋 | 問いかけ | 例 |
|---|---|---|
| コマンド | だれが何をしようとして、その出来事が起きた？ | 手数料を払う → 手数料を払った |
| アクター／外部システム | それをするのはだれ？ どのシステム？ | 申請者、市区町村のシステム |
| ポリシー | 「〜したら〜する」決まりは？ | 払われたら発行する |
| リードモデル | 決めるのに何を見る？ | 交付できる証明書 |
| 集約 | どこで決める？ 何が整合を守る？ | 交付、本人確認 |

## 進め方

1. **レベルを切り替える**　ビューバーのレベルを Design Level（顕微鏡のアイコン）にする。Big Picture（望遠鏡）に戻せば、元の流れだけが見える。
2. **段階ごとに原因を話す**　「申請者が暗証番号を入れて照合する」。AI がコマンド、アクター、集約を書き、出来事とつなぐ。
3. **決まりを話す**　「払われたら発行する」。AI がポリシーにする。
4. **細かい出来事を分ける**　仕組みの細部（予約、承認、内部の失敗や再試行）は、デザインレベルだけの出来事にする（`level design`）。`/es:levels` を送ると、そうすべき出来事・外すべき出来事が候補に出る。

:::tip[コツ]
デザインレベルだけの出来事は、Big Picture では隠れます。前後の出来事はつながったまま描かれるので、みんなで合意した流れは崩れません。Big Picture でも見せたい出来事は、`/es:levels` で外します。
:::

:::caution[よくあるつまずき]
つながりは「起こりうる」ことで、実行の手順ではありません。複数のアクターはどちらか、`emits` はありうる結果です。条件分岐や順番を書き込もうとしないでください。それはモデリング（`.dt`）で決めます。
:::
