---
title: よくあるつまずき
description: ワークショップでつまずきやすいところと、その場での直し方。
---

| つまずき | 起きること | 直し方 |
|---|---|---|
| ゴールを決めずに始める | どこで終わるか分からない。ガイドの地図が「ゴールを決める」のまま | `/es:start` でブリーフを作る（[ブリーフ](../../workshop/brief/)） |
| 付箋が処理名・システム名 | 「支払処理」「OrderService が保存した」 | 過去形の業務の言葉に。`/es:names` |
| 付箋が長い | 図で小さく描かれ、「…」で切れる | 12字ほどに。詳しいことは `///` へ |
| ファシリテーターが書記になる | 参加者が話さなくなる | 参加者の言葉を AI に送ることに徹する |
| 失敗を本流に混ぜる | 本流が一直線に読めない | 例外として分ける（[例外](../../workshop/exceptions/)） |
| 例外がエラーコードの一覧 | 業務として何をするか分からない | 「そのあと人がどうしたか」が分かる例外にする |
| 議論が終わらない | 時間が足りなくなる | 問いとして残して先へ（[問い](../../workshop/questions/)） |
| 問いを推測で埋める | 間違った前提がモデリングに入る | 開いたまま残し、聞く人を決める |
| 早くからコマンドや集約を置く | 流れの合意より設計の議論が先に立つ | Big Picture が終わってから Design Level へ |
| 図を清書する | 見つけた疑問が消える | 問いと出来事は消さない。履歴は git にある |
| 参加者の提案が反映されない | 承認待ちのまま | ファシリテーターがチャットの提案を承認する |
| AI が動かない | 「AI 接続なし」と出る | 起動時の `AI: not started (…)` を見て Claude Code を直す |
